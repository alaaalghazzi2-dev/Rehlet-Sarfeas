# رحلة سرفيس — نسخة Supabase (24.0.0)

نسخة نقل مستقلة مبنية على المصدر المنشور للإصدار 23. لم تُنشر ولم تُربط بقاعدة حقيقية بعد، ولا تغير الموقع القديم. متطلبات التشغيل: Node.js 22+ للتطوير وخادم Cloudflare Worker للاستضافة، ومشروع Supabase مخصص.

## أولاً: حفظ الخطوط القديمة
سجل الدخول إلى إدارة الموقع القديم ثم افتح:
https://rihla-damascus.alaa-alghazzi2.chatgpt.site/api/admin/export
احفظ ملف JSON خارج GitHub. لا تتضمن هذه الحزمة بيانات D1 الحية أو كلمات المرور أو جلساتها أو مفتاح توقيع APK. لا توقف الموقع القديم قبل التحقق من النقل.

## ثانياً: إعداد Supabase
1. أنشئ مشروعاً مخصصاً باسم تختاره. لا تستخدم قاعدة مشروع الصيدليات أو الطباعة.
2. من SQL Editor شغّل محتوى `supabase/setup.sql` مرة واحدة. لا يعيد الملف إنشاء جداول قائمة ولا يحذفها.
3. تأكد من تفعيل Data API وإتاحة schema public. الملف يمنح صلاحيات القراءة ويطبق RLS؛ الكتابة متاحة فقط للحسابات الموجودة في rehlat_admins.
4. من Authentication > Users أنشئ حساب الإدارة ببريدك وكلمة مرور قوية، واجعله مؤكداً وفق إعدادات المشروع. عطّل التسجيل العام؛ التطبيق لا يحتوي واجهة إنشاء حسابات.
5. انسخ UUID الحساب وشغّل في SQL Editor:

```sql
insert into public.rehlat_admins(user_id) values ('ضع-UUID-الحساب-هنا');
```

لا توجد صلاحية تلقائية لأول مستخدم أو لمن يعدل user_metadata. لا يستطيع المستخدم منح نفسه دور مدير.
6. احصل على Project URL ومفتاح Publishable الذي يبدأ بـ sb_publishable_. هذه النسخة لا تقبل service_role أو المفتاح السري. لا حاجة إلى كلمة مرور قاعدة البيانات في التطبيق.

## ثالثاً: إعداد الاستضافة
ملف wrangler.jsonc جاهز لنشر Worker في حساب Cloudflare الخاص بك. الأمر البنائي: `npm ci` ثم `npm run build`. نقطة الخادم: `dist/server/index.js`. عند استخدام ربط GitHub، اختر مستودعك الخاص واضبط بيئة التشغيل:

```
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

هذه متغيرات خادم، لا تُكتب داخل ملفات public. ملف .env.example مجرد مثال؛ ملف .env لا يُقرأ تلقائياً. للتطوير عبر Wrangler ضع القيم في .dev.vars (مستبعد من Git). التشغيل المحلي لدخول الإدارة يحتاج HTTPS لأن كوكي الدخول Secure.
ملف .openai/hosting.json هنا منزوع معرف الموقع القديم؛ الحزمة موجهة لاستضافة مستقلة، وليست تحديثاً يُنشر مباشرة على Sites. لا ترفع dist أو node_modules أو بيانات النسخ الاحتياطية إلى GitHub. GitHub Pages وحده لا يشغّل API الخادم.

## رابعاً: الدخول والاستيراد
افتح /admin وسجّل ببريد الإدارة وكلمة المرور (بدلاً من اسم المستخدم المحلي القديم). لا يحتاج الراكب حساباً.
افتح /admin/import، واختر ملف JSON من الموقع القديم، وراجع عدد الخطوط ثم أكد الاستيراد. الاستيراد يُسمح فقط عندما revision=0؛ بعده يمنع الاستبدال العرضي. يجب استيراد النسخة قبل حفظ أي خط في القاعدة الجديدة. ينسخ الاستيراد بيانات الخطوط، ولا ينقل حسابات D1 أو جلساتها.
بعد الاستيراد راجع خط جادات سلمية وعدد الخطوط ونقاط الذهاب والإياب، وجرّب حفظ تعديل من الإدارة ثم تحديث صفحة الركاب. استخدم /api/admin/export لتصدير نسخة جديدة.

## المصادقة والحماية
- جلسة الإدارة في كوكي HttpOnly/Secure/SameSite=Strict، وتنتهي خلال ساعة كحد أقصى حسب إعداد JWT؛ لا يوجد تجديد تلقائي في هذه النسخة.
- عند انتهاء الجلسة أثناء تسجيل مسار، لا تمسح بيانات المتصفح؛ المسودة المحلية باقية حسب آلية GPS السابقة. سجّل الدخول في تبويب آخر ثم حاول الحفظ.
- كل طلب إداري يتحقق من Supabase Auth ومن جدول المديرين؛ صلاحية الكتابة محمية أيضاً بـ RLS في PostgreSQL.
- حدود محاولات تسجيل الدخول تأتي من Supabase Auth؛ يجب ضبط حدود الطلبات في الاستضافة أيضاً قبل الإطلاق العام، خاصة لأن الطلبات تمر بالخادم.
- تغيير كلمة المرور يتم من /admin/account، ويُطلب البريد الحالي وكلمة المرور الحالية. لإلغاء الصلاحية فوراً احذف صف المستخدم من rehlat_admins. قد تبقى JWT صالحة حتى انتهاء مدتها بعد تسجيل الخروج؛ حذف الصلاحية يمنع الكتابة فوراً.
- استعادة كلمة مرور مفقودة تُدار من Supabase في هذه النسخة. لا توجد شاشة استعادة عامة.
- القراءة العامة تخص شبكة الطرق فقط. لا تضع أرقام هواتف خاصة أو بيانات ركاب أو أسرار في بيانات الخطوط.

## التحقق وحدوده
`npm test` يشغّل اختبارات HTTP بمحاكاة Supabase واختبار SQL/RLS على PostgreSQL مدمج عبر PGlite. شغّل `npm run build` أولاً. لا تمثل الاختبارات ربطاً بمشروع Supabase حي أو اختبار متصفح من سورية. يجب التحقق الفعلي من الاتصال ووقت الاستجابة والاستيراد قبل تحويل المستخدمين.
كود Android للإدارة ما زال يشير إلى رابط الموقع القديم؛ عدّله وأعد بناء APK وتوقيعه بعد تثبيت النطاق الجديد. لا توجد APK جديدة في الحزمة.
المكونات الخارجية للخرائط والمشي والسيارة لم تتغير. نقل القاعدة لا يضمن وحده حل مشكلة VPN.

## الملفات
- supabase/setup.sql: الجداول والصلاحيات.
- supabase-client.js: اتصال REST وحفظ مشروط برقم مراجعة لمنع تعارض التعديلات.
- auth.js: Supabase Auth من الخادم، دون مفتاح service_role.
- public/import-network.js: استيراد النسخة الاحتياطية.
- legacy-d1/: مخططات قديمة للرجوع إليها فقط، لا تشغّلها على Supabase.
- tests/supabase.test.mjs: اختبارات النسخة الجديدة. اختبارات أخرى قد تتضمن افتراضات D1 القديمة.

احتفظ بنسب OpenStreetMap وترخيص Leaflet. إنشاء مستودع خاص لا يغيّر حقوق المكونات الخارجية.
